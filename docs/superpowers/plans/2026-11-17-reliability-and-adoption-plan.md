# 신뢰성·채택 리스크 개선 계획

> **상태:** 계획 초안 2판. Codex 검토를 반영했다(9절). 구현·PR·릴리스는 승인되지 않았다. 체크박스는 승인 후 실행할 작업 목록이며 완료 표시가 아니다.

**Goal:** 처음 쓰는 사람이 ctx-kit을 설치해도 커밋이 막히거나, 기록이 오염되거나, 비공개 내용이 새거나, 지울 수 없게 되는 일이 없도록 한다. 그 뒤에 기능을 더한다.

**Architecture:** 배포물은 지금처럼 `ctx.sh`와 `ctx.config.json` 두 파일이다. 개발은 `src/`의 모듈에서 하고 빌드 스크립트가 `ctx.sh`를 생성한다. 설정 읽기와 경로 검증은 한 곳으로 모은다.

**Tech Stack:** Bash 3.2, Python 표준 라이브러리, unittest. 런타임 의존성·서버·DB·LLM 호출은 추가하지 않는다. 개발 도구로 ruff와 shellcheck를 CI에만 추가한다.

## 1. 기준과 근거

- 작성일: 2026-11-17. 기준: `main` `7309923`.
- 진단 근거: Linux 컨테이너(Bash 5.2, Python 3.13, Git 2.43)에서 전체 테스트 331개 통과(1개 skip)를 확인했고, 아래 F1~F5는 임시 프로젝트에서 직접 재현했다. F6~F8은 코드 판독과 측정이다.
- Windows, macOS, Python 3.7 실환경에서는 실행하지 않았다.
- 선행 문서: [유사 도구 조사](../research/2026-11-01-context-tools-benchmark.md). 이 계획은 그 조사의 "후속 범위"(진단, 유효성 표시)를 구체화하고, 조사에 없던 사용자 리스크를 더한다.

## 2. 경쟁 구도에서 본 위치

기존 조사의 비교표는 유지한다. 이번에 추가로 확인한 사실과 그 의미만 적는다.

| 관찰 | 출처와 확인 수준 | ctx-kit에 주는 의미 |
| --- | --- | --- |
| Claude Code는 CLAUDE.md에서 `@경로` import를 지원하고, Windows에서는 symlink 대신 `@AGENTS.md` import를 권장한다 | [공식 문서](https://code.claude.com/docs/en/claude-md) | symlink만 지원하는 현재 방식은 Windows 기본 설정에서 막힌다. import·복사 모드가 필요하다(P5) |
| Git for Windows는 symlink가 기본으로 꺼져 있고, Developer Mode나 관리자 권한이 필요하다 | [Git for Windows 문서](https://gitforwindows.org/symbolic-links) | 커밋된 링크를 Windows에서 받으면 대상 경로만 적힌 일반 파일이 될 수 있다. 진단 명령이 이를 잡아야 한다(P4) |
| Claude Code에 자동 메모리가 있고, Codex CLI에도 Memories 기능이 보고된다 | Claude: [공식 문서](https://code.claude.com/docs/en/memory). Codex: 제3자 글만 확인, 미검증 | "기억" 자체는 내장 기능과 경쟁하지 않는다. 도구 간 이동성과 사람이 검증 가능한 출처로 차별화해야 한다 |
| claude-mem 사용자들은 worker 포트 충돌로 훅이 모든 프롬프트를 막았다고 보고했다 | GitHub 이슈 [#2899](https://github.com/thedotmack/claude-mem/issues/2899), [#2996](https://github.com/thedotmack/claude-mem/issues/2996). 사용자 보고, 미검증 | 보조 도구가 본 작업을 막으면 사용자는 도구를 지운다. F2와 같은 유형이다(P2) |
| 코드가 바뀌면 메모리가 조용히 낡고, 낡은 기록도 확신 있게 제시된다는 지적이 반복된다 | 실무자 글과 [사전 공개 논문](https://arxiv.org/pdf/2609.05510). 통제된 연구는 찾지 못함 | 기록이 낡았다는 신호를 결정적으로 보여 줘야 한다. F8은 반대로 낡음을 숨긴다(P5) |

**포지셔닝:** 상주 프로세스·DB·모델 호출 없이, 여러 에이전트 사이에서 사람이 확인할 수 있는 근거를 전달하는 로컬 도구. 경쟁 도구의 기능을 따라가지 않고, 그 도구들에서 사용자가 겪는 문제(훅 차단, 상주 프로세스 장애, 낡은 기억, 의도하지 않은 업로드)를 구조적으로 갖지 않는 쪽을 강점으로 삼는다.

## 4. 원칙과 비범위

- 사용자 데이터 보존이 기능보다 우선이다. 기존의 "충돌 시 거부" 동작은 유지한다.
- 보조 도구는 본 작업(커밋, 편집)을 막지 않는다. 막는 동작은 사용자가 켰을 때만 한다.
- 문서의 지원 범위는 CI가 실제로 실행하는 범위와 같게 한다.
- 동작을 바꾸는 변경과 구조만 바꾸는 변경은 같은 PR에 넣지 않는다.
- 비범위: MCP 서버, 임베딩·의미 검색, LLM 요약, 대화 전문 수집, 팀 동기화, 호스팅. 필요성은 P6의 사람 평가 결과로 다시 판단한다.

## 5. 단계별 계획

순서의 이유: P1·P2는 작고 사용자 체감이 크므로 먼저 한다. 구조 분리(P3)는 새 기능(P4·P5)보다 앞에 둔다. 지금 구조에 기능을 더하면 분리 비용이 계속 커진다.

### P0. 안전망 (선행)

이후 변경을 보호할 검사를 먼저 넣는다. 코드 동작은 바꾸지 않는다.

- [ ] CI에 `shellcheck ctx.sh` 추가. 기존 경고는 한 번에 고치지 않고 기준선 파일로 고정한다.
- [ ] 내장 Python을 추출해 `ruff check`(F, E9 규칙)로 문법·미정의 이름을 검사하는 스크립트를 추가한다. P3 이후에는 `src/`를 직접 검사한다.
- [ ] Python 매트릭스에 최신 버전과 최저 버전을 추가한다. `setup-python`이 3.7을 제공하는 러너가 없으면, 문서의 최소 버전을 실제로 실행하는 최저 버전으로 올린다.
- [ ] 테스트 헬퍼 `run_ctx`·`git`(14개 파일에 중복)을 `tests/support.py`로 모은다.

완료 기준: 기존 331개 테스트가 그대로 통과하고, 새 검사가 PR에서 실행된다.

### P1. CLI 일관성 (F3, F4 → R3)

- [ ] 인자 검증 함수를 하나 두고 값이 필요한 모든 옵션에 적용한다.

  ```bash
  need_value() {  # need_value <option> <남은 인자 수>
    if [ "$2" -lt 2 ]; then
      echo "Error: $1 requires a value." >&2
      return 1
    fi
  }
  # --summary|-s) need_value "$1" "$#" || return 1; SUMMARY="$2"; shift 2 ;;
  ```

- [ ] `timeline`이 공통 `read_jsonl`을 쓰게 한다. 공통 파서만으로는 부족하다. `--commit` 필터의 `.startswith()`, 날짜 슬라이스, `.splitlines()`, `join()`이 문자열이 아닌 값에서 예외를 내므로, 표시 경로마다 타입을 확인하고 원래 값을 그대로 보여 준다.
- [ ] 명시적 `--help`와 정상 결과는 stdout, 잘못된 호출의 사용법과 오류는 stderr로 보낸다.
- [ ] 출력 언어는 P1에서 바꾸지 않는다. 언어 선택은 P5에서 다룬다.

완료 기준: 값이 필요한 옵션 전부에 대해 "값 누락 → stderr 메시지와 exit 1" 테스트가 있고, 손상된 타임라인이나 타입이 다른 필드에서 어떤 읽기 명령도 traceback을 내지 않는다.

### P2. 훅 신뢰성 (F1, F2 → R1, R2)

자동 기록을 pre-commit에서 post-commit으로 옮긴다. 성공한 커밋만, 확정된 커밋 ID로 기록한다.

**post-commit에서 기록한다.**

- [ ] post-commit 훅이 `HEAD`의 전체 커밋 ID를 얻고, 그 커밋 객체에서 파일 목록과 diff stat을 구해 한 행을 추가한다. `commit`·`fullCommit`은 실제 값이다.
- [ ] 추가 전에 쓰기 잠금 안에서 활성·보관 로그의 `fullCommit`을 검사한다. 이미 있으면 추가하지 않는다. `backfill`과 실행 순서가 바뀌어도 자동 기록은 커밋당 한 건이다.
- [ ] 사람이 `log`로 남긴 기록은 같은 커밋을 가리켜도 그대로 둔다. 중복 방지는 자동 기록에만 적용한다.
- [ ] `dirty`는 추정하지 않고 기록 시점의 `git status`로 정한다.
- [ ] 컨텍스트 디렉터리의 로컬 Git 스냅샷도 post-commit에서 만든다.
- [ ] pre-commit에서는 더 이상 기록을 만들지 않는다. 기존 `pending` 행은 당시의 시도 기록으로 보존하고 고치지 않는다. 진단 명령(P4)이 개수를 알려 준다.

**커밋을 막지 않는다.**

- [ ] post-commit의 종료 코드는 커밋 결과에 영향을 주지 않으므로, 기록 실패는 stderr 경고로만 남는다. 원인과 복구 명령을 한 줄씩 출력한다.
- [ ] 잠금 대기는 훅에서만 짧게(제안: 3초) 둔다.
- [ ] 기존 post-commit 훅이 있으면 지금의 pre-commit 래퍼와 같은 방식으로 보존하고 먼저 실행한다. 훅 관리 코드는 훅 이름을 인자로 받도록 일반화한다.

**전환.**

- [ ] `hook install`을 다시 실행하면 기존 pre-commit 래퍼를 제거해 원본 훅을 복원하고 post-commit을 설치한다.
- [ ] CLI만 교체하고 재설치하지 않은 상태에서는, 남아 있는 pre-commit 래퍼가 호출하는 `_hook_run_pre_commit`이 재설치 안내 한 줄만 출력하고 exit 0으로 끝난다. 커밋 차단은 CLI 교체 즉시 사라지고, 자동 기록은 재설치 전까지 멈춘다.
- [ ] `status`와 `doctor`가 이 상태를 "훅 전환 필요"로 표시한다.

**알려진 한계와 확인할 것.**

- 병합은 post-commit이 아니라 post-merge를 호출한다. 병합 커밋의 자동 기록은 우선 `backfill`로 보완한다. 지금의 pre-commit도 병합에서는 실행되지 않으므로 동작이 나빠지지는 않는다.
- `--amend`, rebase, cherry-pick, revert는 post-commit을 호출하고 새 커밋 ID를 만든다. 다시 쓰인 옛 커밋의 기록은 남고, 뷰어는 이미 그런 참조를 "확인 불가"로 표시한다.
- rebase 중에는 커밋마다 훅이 실행된다. 권장: rebase 진행 중에는 기록을 건너뛰고 `backfill`에 맡긴다. 구현 시 테스트로 확정한다.
- `--no-verify` 커밋도 post-commit은 실행된다. 지금보다 기록 누락이 줄어든다.

확인한 것: Git 2.43(Linux)에서 일반 커밋, `--no-verify`, `--amend`, rebase, cherry-pick, revert는 post-commit을 호출했고, 메시지가 비어 중단된 커밋은 호출하지 않았으며, 병합과 fast-forward는 post-merge만 호출했다. Codex는 Git 2.42(macOS)에서 병합과 `--no-verify`를 같은 결과로 확인했다. 새 훅 구현과 전환 과정 자체는 아직 실행해 보지 않았다.

영향받는 테스트: 커밋 직후 `pending`을 기대하는 `test_hook_index.py`·`test_git_metadata.py`의 단언은 성공한 커밋의 ID를 확인하는 단언으로 바꾼다. `test_hook_git_query_failure_blocks_commit_without_appending_history`는 "커밋은 성공하고 기록은 추가되지 않으며 경고가 나온다"로 바꾼다. `test_hook_chain.py`는 post-commit 체이닝과 pre-commit 원본 복원을 검사하도록 확장한다. 쓰기 명령 전후로 기존 `pending` 행이 바이트 그대로 보존되는지 검사하는 테스트를 추가한다.

결정 필요: pre-commit 단계에 아무것도 남기지 않으면 커밋을 막을 지점이 없어 엄격 모드(`git_sync.strict`)가 성립하지 않는다. 권장은 엄격 모드를 만들지 않는 것이다. 4절의 "보조 도구는 본 작업을 막지 않는다"와 맞고 훅이 하나로 유지된다. 엄격 모드가 필요하면 pre-commit에 읽기 전용 사전 검사를 따로 둬야 하고, 그 경우 훅 두 개를 관리하게 된다.

완료 기준: 성공한 커밋마다 실제 ID를 가진 자동 기록이 정확히 한 건, 중단된 커밋 뒤 새 기록 0건, 커밋 뒤 `backfill`이 중복을 만들지 않음, 손상된 타임라인에서 커밋 성공, 전환 후 원본 pre-commit 훅이 내용·권한 그대로 복원됨.
